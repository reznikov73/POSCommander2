## FTP: что проверено (09.11.2026)

- WinINet FTP непригоден: пробник на WinINet против UTF-8 сервера вернул имена
  `РїР°РїРєР°` и `С‚РµСЃС‚.txt` вместо `папка` и `тест.txt`. Свой клиент на Winsock
  с `OPTS UTF8 ON` эти же имена читает и пишет правильно.
- `--selftest`: 58 из 58. Добавлены проверки `IsFtpUrl`, `FtpParseUrl`, `FtpMakeUrl`,
  пароля из URL (в собранный URL не попадает), обфускации пароля, строк MLSD/Unix/DOS
  и поля «Сервер» (чистый адрес, готовая строка `ftp://`, отказ `ftps://`).
- `--ftp-test` против `tools/ftp_test_server.py`: 23 из 23. В том числе:
  - список корня — 4 записи (hello.txt, тест.txt, папка, sub);
  - загрузка `файл-тест.bin` 262 144 байта, размер на сервере совпал;
  - скачивание, побайтовое совпадение, прогресс был;
  - RNFR/RNTO → `переименован.bin`, старое имя исчезло;
  - DELE, RMD, временный каталог убран из корня;
  - неверный пароль отклонён, текст ошибки — «Login incorrect (код 530)», пароля в нём нет.
- Прогон с `--mlsd` (сервер отдаёт `MLSD` + `type=dir/file/cdir/pdir`): тоже 23 из 23,
  то есть клиент реально использует MLSD, а не только LIST.
- В окне проверено: диалог «FTP: подключение» (сохранённый профиль, порт 2121, пассивный
  режим), панель `ftp://test@127.0.0.1:2121/`, переход в `папка`, F3 (текст
  «inside folder»), F5 FTP→локально (`local\внутри.txt`, 15 байт), F5 локально→FTP
  (`папка\внутри.txt`, 15 байт), F5 рекурсивного каталога (`папка\вложенная\файл1.txt`
  и `файл2.txt`), F7 `ftp-new`, F2 `renamed.txt`, F8 файла и непустого каталога.
- Найденный баг: в рекурсивном копировании для локального приёмника дочерний путь
  строился через `FtpJoinUrl`, поэтому создавался только верхний каталог, а файлы
  не копировались. Исправлено: `JoinPath` для локальной стороны.
- INI после выхода содержит `[FTP] Count=1`, `0.Pass=242a2037` (обфусцировано,
  не открытый текст), вкладку `ftp://test@127.0.0.1:2121/` — без пароля.

- Отдельная ловушка тестового сервера: в `cmd_mlsd` строки сначала склеивались
  (`\\r\\n` в Python-строке вместо реального CRLF), поэтому MLSD приходил одной
  строкой и клиент видел 0 записей. После исправления сервера — 3 записи и 22/22;
  код клиента при этом не менялся.

- Поле «Сервер» в диалоге: если вставить готовую строку `ftp://admin@194.37.254.233/`,
  раньше она уходила в `GetAddrInfo` как имя хоста и падала. Теперь `FtpParseServerField`
  разбирает схему, `user[:pass]@host[:port]/path`; проверено в реальном диалоге:
  подключение к `194.37.254.233` прошло, корень открылся (10 объектов, кириллица читается).
